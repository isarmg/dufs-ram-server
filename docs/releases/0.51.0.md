# Dufs RAM 0.51.0

管理路由迁移到 Axum，静态管理员认证直接复用 Foundation Axum Adapter。连接限制、真实对端注入、请求 ID、进程信号和有界停机由 Foundation Server 0.7.0 统一承担，产品保留文件安全、流式传输、上传恢复及原有持久操作语义。

- 原生 Web 直接复用 Foundation 0.7.0 的默认内容块、登录卡片、导航、图标与字体；移除旧平台快照，文件页全宽表格，保留中英文、明暗主题和上传业务。登录图标构建为同源 SVG，CSP 不开放 data: 或内联脚本。
- 新公开探针为 `/healthz`（204）和 `/readyz`（最小 ready JSON）；旧路径删除，无别名。
- 登录、列表和操作查询明确 GET-only；文件 HEAD 仍支持上传状态查询，目录和上传查询不虚报 Content-Length。
- 公开静态资源只允许 GET/HEAD，其余方法返回 405。文件操作的 owner、幂等、冲突和 unknown 恢复规则不变。
- 默认访问日志关联同一个平台请求 ID；源读取和 socket 写入各有独立空闲期限。
- 停机先停止准入，排空请求与后台探针，再排空提交，最后关闭状态；硬期限未完成时报告数量并非零退出，不盲目 abort 提交。

本版只接受自身版本的严格 SchemaIdentity。开发和验收使用全新完整实例状态，不提供旧数据库升级、metadata 修改、隐式兼容或任意二进制回退。含旧上传暂存、未决操作或待清理对象的共享树不能随意配上空数据库。真实旧实例应保留，等待独立验证的离线处置方案。

当前 sarmg-upgrade 暂不支持 0.51.0 的备份、验证、恢复或升级；旧版支持声明不适用于本版。release 保持 panic=abort，不能依靠 catch_unwind 隔离 panic。实际验证与尚未通过的门禁记录在[迁移验收记录](../migrations/dufs-axum-contract-changes.md)，发布完成前不得据此声称全部验收通过。
